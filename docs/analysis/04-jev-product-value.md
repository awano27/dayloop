# Jev を中心にすると価値が出るか

出る。出る場所は、台帳を Jev に置き換えることではない。今の dayloop は正しい代わりに、候補・未計画・未着手・未確定をすべて本人が1件ずつ答える。その質問の数が、毎日使うのを止める。Jev を全体の判断に置くと、本人が見るのは「決めきれなかった残り」と、1日1回の確定だけになる。忘れない保証は台帳が残す。

前回の計画（記録だけ、表示だけの提案、日次の自動決定はしない）では、朝と夕方の操作が今と変わらない。Jev の呼び出し料金がログに足るだけで、製品としての差は出ない。

## 価値の単位

朝の `plan` と夕方の `close` が、次の画面になること。

```
2026-09-22  計画
  Jev が今日に入れた    11
  Jev が棚に置いた      24   （7日で再掲。消していない）
  見てほしい             2
  この内容で確定しますか
```

```
2026-09-22  クローズ
  完了 9 / 未完了 1 / 持ち越し 2 / 取り下げ 0
  見てほしい 1（これがあると日は閉じない）
  この内容で閉じますか
```

常駐の通知は「未確定 30 件」から「見てほしい 2 件」に変わる。ロックされた会社 PC で、昼に全件を答える運用より、こちらが使われる。

## 全体を Jev にするための形の変更

Jev は自由文を書けない。今の「理由は文章」のままだと、持ち越し・未完了・取り下げのたびに人が文章を書くので、Jev を全体に置いても質問が残る。判断を閉じた選択肢にする。

| 今 | Jev 中心 |
|---|---|
| 理由は自由文 | 理由コード（待ち / ブロック / 時間不足 / 不要 / 大きすぎる）。文章メモは任意で、空でもコードがあれば不変条件2を満たす |
| キーワードが候補を作る | Jev の Choice が先。キーワードは Jev が落ちたときの経路 |
| 候補は採用か却下 | 高い確信の情報共有は `shelved`（棚）。`rejected_refs` には入れない。7日で振り返りに戻るので、不変条件4（消えない）は残る |
| 1件ずつ状態を書く | Jev は `proposed_state` を書く。確定の1回で台帳へ反映する |
| 分割タイトルをその場で考える | 生成 LLM が案を書き、Jev の Noul が「元の仕事を分けているか」を見る。否なら人に残す |

日付、空き時間、持ち越し回数、予定の終了判定はこれまで通り Rust がラベルにしてから渡す。Jev に計算はさせない。

## 人が必ず残る地点

- Choice が `要確認`、または確信が帯の下
- 前日が開いたまま（不変条件5）
- 提案を確定する1回（`confirm_plan` / `close`）。ここを省くと、誤った Choice がそのまま台帳になる
- Jev が 429 / 529 / タイムアウトのとき。その回は今の全件質問に戻る。日は止まらない

空 Enter で1件目の「完了」を実行する今の CLI は、この製品では使わない。確定はサマリに対する1問だけにする。

## 台帳を捨てると価値が消える

Jev に「今日を閉じて」と頼む製品は、スキーマに合った誤判断をそのまま完了にする。dayloop の既存の約束（開いたタスクが残る日は閉じない、理由のない未完了は書けない、却下した参照は再提示しない）は、Jev の保証の外にある。価値は「Jev が量を減らし、台帳が残りを拒否する」組み合わせにある。

CEO 自身が、部分点は自動実行の根拠にならず、現時点の Jev は `will work` の側ではない、と書いている。だから全件を無確認で確定はしない。サマリの1回と、棚の7日再掲が、その留保に対する製品側の答えである。日本語件名での帯は、自分のメールで較正してから `decide` に上げる。較正中も画面の形は同じで、提案はサマリに出るが台帳には書かない。
