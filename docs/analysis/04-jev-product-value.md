# Jev を中心にすると価値が出るか

出る。質問が毎日同じだけ残る形では、まだ人が介在し続ける。価値が積み上がるのは、答えた内容が判断グラフの枝になり、同じ状況の次から人が出なくなるときである。育ち方は [05-decision-graph.md](05-decision-graph.md)。

今の dayloop は、候補・未計画・未着手・未確定をすべて本人が1件ずつ答える。その回数が、毎日使うのを止める。Jev は枝がまだ無い節の初回だけを判断し、本人がその回答を一度採用すると、翌日からその節は自動で台帳まで進む。忘れない保証は台帳が残す。

前回の計画（記録だけ、表示だけの提案、日次の自動決定はしない）では、朝と夕方の操作が今と変わらない。Jev の呼び出し料金がログに足るだけで、製品としての差は出ない。

## 価値の単位

同じ仕事への質問が、翌日には出なくなること。

```
月曜  経費精算をどうしますか
      → 時間不足で持ち越し（この回答が枝になる）

火曜  経費精算は質問なしで持ち越し
      新しい節 1件だけ通知

金曜  既知の節だけ。通知なし。日は閉じる
```

常駐が鳴らすのは、枝の無い節が残った日だけである。

## 形の変更

Jev は自由文を書けない。今の「理由は文章」のままだと、持ち越し・未完了・取り下げのたびに人が文章を書くので、Jev を全体に置いても質問が残る。判断を閉じた選択肢にする。

| 今 | Jev 中心 |
|---|---|
| 理由は自由文 | 理由コード（待ち / ブロック / 時間不足 / 不要 / 大きすぎる）。文章メモは任意で、空でもコードがあれば不変条件2を満たす |
| キーワードが候補を作る | Jev の Choice が先。キーワードは Jev が落ちたときの経路 |
| 候補は採用か却下 | 高い確信の情報共有は `shelved`（棚）。`rejected_refs` には入れない。7日で振り返りに戻るので、不変条件4（消えない）は残る |
| 1件ずつ状態を書く | 回答は枝になる。次の同じ節は store まで自動で進む |
| 分割タイトルをその場で考える | 生成 LLM が案を書き、Jev の Noul が「元の仕事を分けているか」を見る。否なら人に残す |

日付、空き時間、持ち越し回数、予定の終了判定はこれまで通り Rust がラベルにしてから渡す。Jev に計算はさせない。

## 人が出る地点

- どの節にも枝が無く、Jev が `要確認` か帯の下を返したとき。その回答が枝になる
- 親の枝が割れていて、件名にも状況にも枝が無いとき
- 自動で進んだ判断を `revise` で直すとき。直した枝が次から効く
- 前日が開いたまま（不変条件5）
- Jev が落ち、かつ枝も無い節。既知の節はそのまま進む

毎日の一括確定は置かない。未知が 0 件の日は、`plan` も `close` も質問なしで終わる。

## 台帳を捨てると価値が消える

Jev に「今日を閉じて」と頼む製品は、スキーマに合った誤判断をそのまま完了にする。dayloop の既存の約束（開いたタスクが残る日は閉じない、理由のない未完了は書けない、却下した参照は再提示しない）は、Jev の保証の外にある。価値は「Jev が量を減らし、台帳が残りを拒否する」組み合わせにある。

CEO 自身が、部分点は自動実行の根拠にならず、現時点の Jev は `will work` の側ではない、と書いている。自動で繰り返すのは、本人が一度答えた枝だけにする。Jev の確信度だけでは枝を生やさない。棚の7日再掲は残り、そこで選び直せば枝が差し替わる。日本語件名の帯は、未知の20件で人の回答と突き合わせてから書く。
