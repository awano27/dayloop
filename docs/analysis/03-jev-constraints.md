## モデルが返すもの

Jev（TypeSafe AI、System One）は文章を生成しない判断モデルである。入力は状況 `state` と、聞きたいことを定義する `questions`。

| 型 | dayloop での対応 |
|---|---|
| Choice | 渡した候補から1つ。候補ごとの確率と confidence。候補数の上限は公式ブログの説明で 255 |
| Score | 順序のある尺度上の分布 |
| Noul | 1つの命題の 0〜1。他の Noul と足して 1 にする必要はない |

Choice が返す文字列は、こちらが候補として渡した値である。理由文、分割後のタイトル、返信メールは生成できない。

「幻覚 0%」はスキーマ一致の話である。公式ブログの留保は、その数字が実測の誤判断率ではない、というもの。候補の外は出さない。正しい候補を選ぶ保証ではない。候補リスト自体が誤っていれば、合法な誤答になる。

## 役割

スライド 09-18 が実装パターンとして固定している式を、そのまま境界にする。

- 判断は Jev
- 実行はコード
- 生成は LLM

ゲームデモと同じ分担にする。合法手はコードが列挙し、Jev は1手を選ぶ。dayloop では合法手がすでに `engine::Question` の `options` である。

CEO（Diogo Almeida）の留保も境界にする。

- 部分点は自動実行の根拠にしない。`might work` と `will work` は別で、現時点の Jev は後者ではない、と本人が置いている。
- confidence で切り、常時置換はしない。低いときは人、または生成 LLM。
- 大きな企業データの抽出は Jev 単体の仕事ではない。抽出器と組み、confidence で人の確認を減らす。
- 質問は小さく、原子的にする。
- 計算と日付はコード。公式の不得意（jaggedness）は計算、計数、日付比較、間接参照、長い無関係な state、字義どおりの読み。

通信失敗（スライドが挙げる 429 / 529、認証失敗、タイムアウト）でも `plan` / `check` / `close` は止まれない。キーワード規則と人手の質問が残る。

## dayloop が Jev に渡してよい仕事

### 1. メール抽出結果の仕分け（Choice + Noul）

抽出はこれまで通り Outlook COM（またはフィクスチャ）。渡す state は短い。

- プレフィックスを除いた件名
- 送信者の表示名
- フラグ、未読
- 既存ルールが付けた reason（`flagged` / `keyword` / `important_sender`）

本文は既定で送らない。`read_body = true` かつ設定で明示したときだけ、既存の先頭 2000 文字を state に含める。

質問は1回の呼び出しにまとめる（追加質問の遅延は小さい、という公式説明に沿う）。

- Choice: `タスク候補` / `情報共有` / `要確認`
- Noul: 「今日中の対応が必要か」（命題は1行。必要かどうかの業務決定そのものはコードと人が持つ）

候補から `要確認` を外さない。二択だけにすると、根拠不足でもどちらかに落ちる。

`情報共有` は候補箱に入れない、までを自動化するのは計測の後。最初のモードは記録だけ。

### 2. 既存の質問に対する提案（Choice）

`close_task` / `check_task` / `candidate` / `carry_blocked` の選択肢は、いまの `options[].label` をそのまま Choice の候補にする。新しい自由文の選択肢は足さない。`後で決める` と、閉じる場面の既存4択を残す。

state に渡す事実は、Rust が先にラベル化したものだけ。

- 状態名、タイトル
- `carried_count` は計算済みの整数（「何回目か数えて」とは聞かない）
- 期限は `overdue` / `today` / `future` / `none`（日付の比較は聞かない）
- 見積と空き時間は `fits` / `over` / `unknown`

### 3. 生成が要る仕事は Jev の外

理由、分割タイトル、振り返りメモは文章である。Jev には頼まない。
生成 LLM（既存の `DAYLOOP_LLM_ENDPOINT`、または Copilot）が下書きを出してもよい。空の理由を台帳へ書く経路は、不変条件2が拒否したままにする。下書きを保存するのは人が確定したあとだけ。

## 自動実行の段階

confidence は正答率そのものではない。Choice の confidence は分布の尖りで、公式は「0.9 なら正答率 90%」とは書いていない。候補ごとの確率を見て、自前データで境界を切る。公式モデルページは学習の主言語を英語とし、CJK は精度が落ちる、と注記している。英語の閾値を日本語の件名に流用しない。

| モード | 振る舞い | いつ有効にするか |
|---|---|---|
| `off` | 今と同じ。ネットワークを呼ばない | 既定 |
| `shadow` | 呼び、選択と確率をログする。質問の既定も台帳も変えない | キーがあり、評価用の日本語データが置けるとき |
| `suggest` | 質問の横に提案を出す。Enter の既定（選択肢 0）は変えない | shadow の記録が残ってから |
| 自動で候補を捨てる / 日を閉じる | この計画には含めない | CEO の留保が変わるか、日本語の正解付き評価で帯ごとの見逃しが許容できてから、別の決定にする |

CLI は空 Enter を選択肢 0 にする。選択肢 0 は完了や「今日やる」であることが多い。提案のために既定インデックスを変えると、Enter が Jev の選択を実行する。それは自動実行になるので、`suggest` ではインデックスを動かさない。

評価セットは英語デモではなく、本番に近い日本語の件名 20 件を先に置く。正解ラベル付きで、confidence の帯ごとに正答と見逃しを数える。帯の数値（例としてスライドが挙げる 0.9 / 0.7）は例であり、20 件の結果が出るまで設定値にしない。

## 呼ばない条件

- 台帳の遷移（`close_day`、`carry_over`、`transition`）の成否
- 日付、空き分数、持ち越し回数の計算
- メールボックス全体の抽出、添付、アドレス帳
- 画像（公式に画像入力は無い。画面は先に state へ変換する）
- Open-Jev などコミュニティ実装を公式 Jev と同一視した経路。プロンプトインジェクションの報告は公式と分けて扱う

## 接続

呼べる経路は複数ある（直販、Vercel AI Gateway の `typesafe-ai/jev`、Cloudflare Workers AI、OpenRouter、ロリポップ！）。ロックダウン PC ではプロキシと、どの経路がユーザー権限で開くかが先に決まる。doctor はキーの有無と、設定した経路への TCP 到達だけを見る。ユーザーの件名を診断用に送らない。

キーは環境変数に置く。リポジトリと `config.toml` のサンプルには書かない。`jev-mcp` / `jev-cli` はエージェントが分岐だけを渡す公式の入口として存在する。dayloop 本体は単一 exe のまま、判断が要るときだけ HTTP（または、実装時に SDK が示すクライアント）を呼ぶ。exe が Jev の MCP サーバーを兼ねる必要はない。

実装に入る前に、採用する SDK の版で次を固定する。

- state と questions のフィールド名
- Choice / Noul を1リクエストに同居できるか
- confidence と候補確率のフィールド名
- 429 / 529 の実際のステータス
- 日本語件名でのレイテンシ（公式の幅は 70〜500ms。日本からの観測はそれより遅い、という投稿がある。未計測のままタイムアウトを 70ms にしない）

## 採用する改善と、見送り

採用する。

- キーワード先勝ちの横に、Choice（タスク候補 / 情報共有 / 要確認）と Noul（今日中か）を置く
- 朝昼夕の質問に、合法手の中からの提案を添える
- 失敗時は既存の規則と人手に戻す
- 日付と件数は Rust のラベルにしてから渡す
- 日本語 20 件の shadow 評価を、自動化より先に置く

見送る。

- Jev による日次クローズ、持ち越し、取り下げ
- Jev による理由文と分割タイトル
- 本文の既定送信
- Enter 既定の書き換え
- コミュニティ互換モデルへのフォールバック
