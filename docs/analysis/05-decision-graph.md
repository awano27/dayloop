# 回答がグラフになり、次から人が出ない

人が毎回介在する運用は、ここでの製品の形ではない。本人が入れた回答は、その場の台帳更新で終わらせず、判断グラフの枝にする。同じ状況が次に来たら、その枝を辿って台帳まで進み、質問を出さない。新しい節だけが人に戻り、その回答がまた枝になる。日を追うほど質問は減る。

Jev は、グラフに枝が無い節の最初の判断である。Jev の出力だけでは枝を生やさない。本人が一度その判断を採用するか、自分で選び直したときに枝が生える。翌日からその節は Jev も人も通らない。

## グラフの中身

節は閉じたキーだけを持つ。文章そのものは節にしない。

| 節の種類 | キー |
|---|---|
| 件名 | 空白を畳んだタスク名または件名 |
| 状況 | 判断の種類、送信者、期限ラベル、空きラベル、フラグ、持ち越し回数の帯 |
| 送信者 | 表示名 |
| 取り込み元 | `outlook` / `meeting` / `alert` / `manual` |

枝は「この節ならこの選択肢と理由コード」である。人が答えたときだけ生える。`support` は同じ回答が重なった回数、`active` はその節の今の答えである。選択肢を変えた回答は、古い枝を残したまま新しい枝を `active` にする。監査は残り、次の適用は新しい枝だけを使う。

辿る順は、具体から粗い方へ。

1. 件名の節に active な枝がある
2. なければ状況の節
3. なければ送信者の節
4. それでも無ければ Jev。Jev に渡す state は、その送信者の枝が1本あるときそれだけを足す。グラフ全体は渡さない
5. Jev も `要確認` か不通なら人に聞く

親どうしで答えが割れているときは適用しない。人の回答が、より具体的な節（件名、なければ状況）に枝を書く。次の同じ件名は親の不一致を見ずに決まる。

## 適用

枝が当たった行は、その場で台帳の関数へ入れる。`transition`、`carry_over`、候補の棚、今日の予定。提案列で止めない。理由コードは枝が持っているので、不変条件2を満たしたまま人が文章を書かなくてよい。

当たらなかった行だけが「新しい節」として残る。残が 0 なら `plan` も `close` も質問なしで終わる。`serve` はその日、通知を出さない。残が 1 件以上なら、その件数だけ通知する。

棚はこれまで通り `rejected_refs` に入れない。7日後に振り返りへ戻ったとき、人が「棚のままでよい」と答えれば、その件名の枝が棚のまま強くなる。別の答えなら枝が差し替わる。

## 成長の例

1. 月曜、「経費精算」を時間不足で持ち越す。件名の節に枝ができる。
2. 火曜、同じタイトルは質問せず持ち越す。回数の上限に達したら、その先は別の節（持ち越し上限）として一度だけ聞く。
3. 「田中」からのメールを続けてタスクにしたら、送信者の節に枝ができる。次の田中の未知の件名は、件名の節が無くてもタスク候補になる。
4. 水曜、その自動判断を「棚」に直す。送信者の枝は棚に替わり、件名の節にも棚の枝ができる。木曜以降の同じ件名は棚になる。

直したその回から次に効く。まとめて学習し直すバッチは無い。

## 人がまだ出るところ

- どの節にも枝が無く、Jev が `要確認` か帯の下を返したとき
- 親の枝が互いに割れているとき
- グラフが適用したあとに、本人が `dayloop revise` で選び直すとき。これが次の枝になる
- Jev が落ち、かつ枝も無いとき。キーワードと全件質問は、この冷えた節だけに使う

毎日のサマリ確定は置かない。枝が無い日の最初だけ質問が多く、枝が埋まった日は画面が件数の報告になる。

## 台帳との境界

グラフが選んでよいのは、すでに合法な選択肢だけである。open が残っていれば日は閉じない。枝の適用は store の同じ関数を通す。候補外のラベルは枝にしない。

Jev の確信度だけで枝を生やさない。生やすのは本人の回答だけである。こう分けると、自動で進む判断は自分が一度教えたものに限られる。
