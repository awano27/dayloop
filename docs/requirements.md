# dayloop 要件定義書

対象は 2026-09-23 時点の製品である。将来の段階ではなく、今のコマンドと、この開発 PC で確認した動作を書く。

## 1. 目的

1日のタスクを、朝に計画し、昼に確認し、夕に確定する。未確定が残る日は閉じない。同じ判断はグラフに残し、次から質問しない。過去の答えが無いものだけを Jev に聞き、残すか捨てるかを決める。

## 2. 利用者

一人で使う。データはこの PC の `%LOCALAPPDATA%\dayloop` に置く。管理者権限は要らない。ネットワークへ台帳は送らない。

操作口は次の3つである。

- コマンド
- MCP（stdio）。Grok と Codex には `dayloop mcp` を登録してある
- 常駐（`serve`）。設定した時刻に非対話で朝昼夕を回す

## 3. 1日の要件

| 要件 | 受け入れ |
|---|---|
| 前日が閉じるまで今日を確定できない | 未確定のタスクが残る日は `closed_at` を入れない |
| 朝は積み残し、候補、未計画、今日の予定の順 | `plan` がこの順で聞く |
| 日中は次の1件 | `next` は証跡と既知の枝を先に適用し、残った先頭を出す |
| 昼は未着手を確認する | `check` |
| 夕は1件ずつ決着する | 完了、未完了、持ち越し、取り下げ。残ると閉じない |
| 持ち越しは3回まで | 4回目は分割、取り下げ、期限変更まで止まる |
| 完了は理由なしでよい。未完了、持ち越し、取り下げは理由が要る | 空の理由は拒否する |
| 同じ判断の2回目以降は質問しない | 件名、状況、送信者の順に枝を辿り、当たれば台帳へ書く |
| 答えの修正は履歴を残す | `revise` は古い枝を残し、新しい枝だけを有効にする |

順番は、期限超過、今日が期限、持ち越し回数、空き時間に収まる見積、短い見積の順である。同点は `prefer` で覚えた順を使う。

## 4. 入口の要件

届くものだけを読む。届かない入口は、理由を1行出して終了コード 0 で終わる。偽の完了はしない。

| 入口 | 要件 | 今の到達 |
|---|---|---|
| 手入力 | `add` で今日の予定か未計画に入れる | できる |
| 議事録ファイル | `inbox` の txt、md、html。アクション、フォローアップ、宿題の行だけを候補にする | この PC で確認した |
| Gmail | ブラウザで受信トレイを開き、最大5通を開いて Jev が残すか捨てるかを決める | 一覧と開封は確認した。広告5通は skip になった |
| Outlook のウェブ | Gmail と同じ。URL だけ違う | コードはある。この PC では受信トレイまで確認していない |
| Azure DevOps Boards | `https://dev.azure.com/pcedx/pcedx-1/_workitems/recentlyupdated/` を開き、同じ判断をする | 作業項目を残せる。保存する題名からは New Work Item や Column Options を外す |
| Teams のブラウザ | 同じブラウザ読み取り | コードはある。この PC では一覧まで確認していない |
| クラシック Outlook | COM でメールと予定を読む。本文は既定で読まない | この PC には COM が無い |
| Teams チャット、Graph のメール | トークンがあるときだけ | この PC ではトークンが無く、読んでいない |
| GitHub | 自分に割り当てられた Issue と PR。マージ済み PR と closed の Issue は完了 | `GITHUB_TOKEN` が無くても、`gh auth login` 済みならその資格情報で読む |
| Jira | 自分に割り当てられた未完了。done なら完了 | 接続情報が無く、実物は読んでいない |
| DevOps API | 組織名と PAT か `az login` | ブラウザ読み取りとは別。この PC の `az` 資格情報では Boards が 401 になり、API では読めない |
| 今見ている Outlook / Teams | `capture` が前面の窓の文章だけを読む。クリックも入力もしない | 本文が取れなければ「取得失敗」。依頼が無かったことにはしない |

ブラウザ読み取りで Jev に渡してよい操作は「開く」と「終わり」だけである。送信、削除、返信、転送、作成は選択肢に入れない。言語の選択画面は候補にしない。

`capture` は、届いたものを集める入口とは別である。今前面にある新しい Outlook か Teams の文章を、その場で1回読む。既定では本文を Jev に送らない。`--send` のときだけ、種類、自分との関係、優先度、既存タスクとの関係、次の扱いの5つを選ばせる。不明と確認が必要を選択肢に残す。原文と評価と、採用、修正、保留は上書きせずに残す。採用しても今日の予定には入らない。完了にもしない。窓の部品の番号は保存しない。

## 5. Jev の要件

- 既定はオン。接続先が空なら `https://api.typesafe.ai/v1/systemone`
- 鍵は `DAYLOOP_JEV_API_KEY`、無ければ `TYPESAFE_API_KEY`
- 過去の答えがある節には聞かない
- 確度 0.5 以上の keep、または台帳用の閉じた選択肢だけを書く。下限を設定していればその値を使う
- 確度が足りない、要確認、呼び出し失敗は人が選ぶ
- 開いたタスクが残る日を、Jev もグラフも閉じてはならない
- 送るのは正規化した件名、期限、空き、持ち越し回数、閉じた選択肢、ブラウザで開いた本文の先頭だけである。メール全文を学習用に送る要件はない

## 6. 完了の要件

次のときだけ、人の回答なしで完了にしてよい。

- マージ済みの GitHub PR
- closed の GitHub Issue
- Jira の statusCategory が done
- Azure DevOps の状態が Closed、Done、Completed、Removed、Resolved
- 予定の終了時刻を過ぎた会議の準備タスク

それ以外の「終わったかもしれない」は完了にしない。

## 7. 常駐と設定

平日の既定時刻は、計画 08:30、確認 13:00、確定 18:00、振り返りは金曜 18:30 である。未確定が残るフェーズは通知し、同じ日に二度は走らない。ブラウザは `intake browse` のときだけ開き、朝の `plan` では開かない。

## 8. この PC で確認できたこと

- 議事録ファイルからアクション2件を候補にした
- Gmail の受信トレイを開き、広告5通を Jev が skip した
- DevOps の最近更新した作業項目から `test` を1件残した
- 鍵の無い GitHub、Jira、Teams、組織名の無い DevOps API、COM の無い Outlook は、終了コード 0 で理由を出した
- 不正なブラウザ指定は終了コード 1 で拒否した

## 9. 要件にしないこと

- 会社支給の Graph トークンや Teams トークンを前提にしない
- デスクトップの新しい Outlook と新しい Teams の内部キャッシュは読まない
- 画面のクリックで送信や削除をしない
- 20件の帯が空のままなので、確度 0.5 は測定結果ではなく初期値である
