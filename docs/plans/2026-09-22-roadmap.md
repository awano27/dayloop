# dayloop 開発計画（2026-09-22）

分析: [現状](../analysis/01-current-architecture.md)、[穴](../analysis/02-gaps.md)、[Jev の制約](../analysis/03-jev-constraints.md)

## 方針

台帳が忘れを防ぐ、という段階3までの約束は維持する。Jev は文章を書かない判断層として、抽出済みの短い state と、コードが列挙した選択肢にだけ使う。実行（状態遷移、日付、件数、日を閉じること）は Rust のまま。文章が要る仕事は人、または生成 LLM の下書きで、空の理由は保存しない。

既定は Jev オフ。キーが無い PC でも今と同じコマンドが動く。

## 段階

```
3.1 台帳と質問を一系統にする
  → 3.2 Jev は shadow（記録のみ）
    → 3.3 Jev は suggest（既定の Enter は動かさない）
      → 4 新しい Outlook は Edge。仕分けは 3.2 と同じ質問
        → 5 VS Code 拡張（exe が止まる PC）
          → 6 会議・アラート・勤怠
            → 7 M365 Copilot は MCP の質問を順に聞く
```

3.2 より前に、候補を自動で捨てるモードは作らない。3.3 の次も、自動クローズは別決定が要る。

## 段階 3.1 台帳と質問を一系統にする

Jev の前にやる。合法手が二系統だと、提案先と実行先がずれる。

### 3.1.1 前日未クローズは台帳が拒否する

- 変更: `src/store.rs` の `confirm_plan`、`src/engine.rs` の `plan_view`、`src/tools.rs` の `confirm_plan`
- `unclosed_days_before` に open タスクが残るあいだ、`confirm_plan` はエラーを返す
- `plan_view` はそのあいだ `confirm_plan` の質問を出さない
- テスト: 昨日が open のまま今日を `confirm_plan` すると失敗する。昨日を閉じたあと成功する
- CLI の `plan_ritual` の早期 return は残してよい。拒否の本体は store に置く

### 3.1.2 質問カタログを engine に寄せる

- 変更: `src/rituals.rs`、`src/tools.rs`
- `rituals` の `ui.choose` 文言を、`engine::Question` の `options[].label` から出す
- MCP の description から `resolve_with` を消し、`options[].tool` と `needs` に合わせる
- テスト: `plan_day` / `check_in` / `close_day` / `retro_week` のツール説明に `resolve_with` が無い

### 3.1.3 親子とスキーマ版

- 変更: `src/model.rs`、`src/store.rs`
- `Task.carried_from` を読み書きし、JSON に出す
- `user_version`（または隣接テーブル）でスキーマ版を持つ。既存 DB には足りない列を `ALTER` する
- テスト: 持ち越し後の新タスクから元 ID が辿れる。空の旧 DB ファイルを開くと列が足される

### 3.1.4 判断の前処理（純粋関数）

- 追加: `src/facts.rs`（名前は実装時にこの1語へ寄せる）
- 入力: 日付文字列、期限、見積分、その日の予定（開始・終了）
- 出力: `DueRelation`（`overdue` / `today` / `future` / `none`）、`Fit`（`fits` / `over` / `unknown`）
- 空き時間は予定の重なりを Rust で分に直してから見積と比べる。予定が無い日は `unknown`（0分とは扱わない）
- テスト: 予定 10:00–11:00、見積 30 分 → `fits`。見積 120 分 → `over`。期限が昨日 → `overdue`
- 祝日カレンダーはこの段階では足さない。土日除外は `next_workday` のまま。祝日は段階6の勤務カレンダーと一緒に決める

### 3.1.5 CI

- 追加: `.github/workflows/ci.yml`
- `ubuntu-latest` で `cargo test`
- Outlook COM の実機テストはジョブに入れない。フィクスチャのパイプラインテストが CI の取り込み保証
- `scripts/smoke.sh` の既定バイナリを、Windows の `.exe` 固定から、存在するバイナリ名へ変える

完了条件: `cargo test` が CI で緑。`confirm_plan` が不変条件5を store で拒否する。ツール説明に廃止フィールドが残っていない。

## 段階 3.2 Jev shadow

ネットワークを呼んでも、台帳と質問の既定は変えない。

### 設定

`config.toml` に足す。サンプルのキー値は空。

```toml
[jev]
mode = "off"          # off | shadow | suggest
route = ""            # 実装時に SDK が示す経路名。空なら呼ばない
timeout_ms = 2000
```

キーは環境変数 `DAYLOOP_JEV_API_KEY`。doctor は変数の有無と、route が空でないときの到達だけを表示する。件名は送らない。

`mode = off` またはキー無しのときはクライアントを作らない。

### クライアント

- 追加: `src/jev.rs`
- 公開関数は狭い。`fn classify_mail(state: MailState) -> Result<MailJudgement>` と `fn suggest_choice(question: &Question, facts: &Facts) -> Result<ChoiceSuggestion>`
- 中の HTTP 形は、採用 SDK の現行フィールドで書く。スライドの説明用 JSON はコピーしない
- タイムアウト、401、429、529、接続失敗は `Err` にせず `Judgement::Unavailable { reason }` を返す。呼び出し側はキーワード規則と人手に戻し、`serve.log` に1行残す
- 返却値が候補外なら採用しない（スキーマ保証が崩れても台帳を守る側で落とす）

### メール仕分け

- 変更: `src/intake/mod.rs`（候補を書く直前）
- state は [制約文書](../analysis/03-jev-constraints.md) の短い項目だけ
- Choice 候補は `タスク候補` / `情報共有` / `要確認`。境界の説明文は `src/jev_prompts.rs` に版付きの定数で置く（選択肢の定義が品質を決める、という 09-14 の指摘）
- Noul は「今日中の対応が必要か」の1命題
- `shadow` では結果を `jev.log`（データディレクトリ）へ追記し、候補の追加有無は今の `mail_hit` のまま
- 本文を state に含めるのは `read_body = true` かつ `[jev] send_body = true` のときだけ。既定は false

### 質問の記録

- `plan` / `check` / `close` / `retro` で質問を出すとき、`shadow` なら Choice の結果を同じログへ書く
- `Question` の JSON 形は変えない（クライアント互換）

### 評価セット

- 追加: `fixtures/jev/ja-mail-20.toml`（件名、送信者表示名、フラグ、期待 Choice）
- 追加: `tests/jev_shadow.rs`。HTTP はモック。候補外の値は捨て、Unavailable のとき `mail_hit` の結果が残る
- 実 API を CI では呼ばない
- 人手の手順を `docs/jev-eval.md` に書く。20件を実経路で1回流し、帯ごとの正答と見逃しを表にする。閾値の数値はこの表の前に設定ファイルへ書かない

完了条件: `mode = off` の振る舞いが段階3.1と同一。`shadow` で API 失敗しても `intake` の終了コードと候補生成が今と同じ。評価手順の文書がある。

## 段階 3.3 suggest

shadow のログが1回分以上あってから有効にする。機能フラグは `mode = suggest`。

- `Question` に任意フィールド `suggestion` を足す。`{ label, probabilities, confidence, unavailable }`
- `label` は既存 `options` のどれか。一致しなければフィールドを省く
- `default` インデックスは変えない。CLI の空 Enter は今と同じ選択肢 0
- 表示は質問の下に1行: `提案: <label>（confidence <数>）`。Unavailable のときは行を出さない
- MCP の古いクライアントは未知フィールドを無視できる形（追加のみ）
- 候補の自動却下、自動採用、`close_day` の自動成功は実装しない

完了条件: suggest でも Enter が段階3.1と同じ遷移をする。提案ラベルが options に無い応答は表示されない。

## 段階 4 新しい Outlook（Edge）

doctor がすでに案内している段階。COM が無い、または `olk.exe` のみのとき。

- `Source` の実装を足す。画面や HTML から `MailItem` / `CalendarItem` へ変換するのはこの実装の仕事（Jev にページ全体を渡さない）
- 認証はユーザーが既に Edge でサインインしているセッションの範囲に限る。管理者権限とアプリ登録は要らない方式を先に調べ、無理ならこの段階を止めて決定事項に残す
- 仕分けは段階3.2の同じ関数。Edge でも COM でも `mail_hit` がオフライン基準で、Jev は shadow / suggest のまま
- 日本語ロケールの COM Restrict（`yyyy/MM/dd HH:mm`）は、クラシック Outlook が触れる PC で1回確認し、`docs/decisions.md` に結果を書く

完了条件: COM 失敗が終了コード 0 のまま、Edge 実装がフィクスチャと同じ `ingest` を通る。実機が無い環境ではフィクスチャが緑であればこの段階の自動テストは足りる、と文書に明記する。

## 段階 5 VS Code 拡張

AppLocker / WDAC で exe 更新が止まる PC 向け。doctor の推奨と一致させる。

- 第1弾は拡張が `dayloop mcp` を起動し、`questions` をサイドバーに出す。遷移は既存ツール呼び出し
- `suggestion` があれば表示し、ボタンの既定フォーカスは options の 0 番のまま
- exe 自体が起動できない場合の台帳移植（WASM や TypeScript 再実装）は、doctor が「exe も VS Code も無い」と出た実績が手元で確認できるまで始めない

完了条件: 拡張から `get_today` と、open が残る `close_day` が質問を返す。質問に答えきるまで日が閉じない。

---

## 段階 6 会議・アラート・勤怠

取り込み元を増やす。不変条件は変えない。

- 会議: 既存の会議準備候補に加え、終了時刻を過ぎた予定を「記録するか」の候補にする。終了判定は Rust の時刻比較
- アラート: `source = alert` の候補追加。発生元の取得方法は、その時点でユーザー権限だけで読めるものに限る
- 勤怠: Edge 経由の別コマンド。勤怠の打刻失敗をタスクの open と混ぜない。日次クローズの条件はタスクのまま
- 祝日: 勤怠と同じカレンダー設定で `next_workday` を拡張する。設定が無いときは土日のみ、今と同じ

Jev を使うなら、会議準備の要否を Noul 1個にできる。日時の解釈はコードのまま。

---

## 段階 7 M365 Copilot

Copilot は生成側。分岐は dayloop の MCP がすでに持っている。

- クライアント設定は `docs/mcp-clients.md` の Copilot 節を、段階3.1のツール説明に合わせて更新する
- Copilot への手順は「`questions` を1件ずつ本人に聞き、`options[].tool` を `needs` が揃ってから呼ぶ。`tool: null` は呼ばない。`close_day` は open が残るあいだ繰り返す」
- Jev の `suggestion` は Copilot へのヒントであり、呼ぶツールを suggestion だけで決めてよい、とは書かない
- 理由が要るときは Copilot が下書きを本人に確認する。確認前に `set_not_done` / `carry_over` / `drop_task` を呼ばない

## 決定を後に残すもの

実装しながら `docs/decisions.md` に「選んだ扱い」を足す。今は選ばない。

| 論点 | 決めるタイミング |
|---|---|
| ゲートウェイ（直販 / Vercel / Cloudflare / ロリポップ） | 対象 PC のプロキシで到達を見てから |
| confidence の二段閾値の数値 | `docs/jev-eval.md` の20件の後 |
| 候補の自動却下 | 日本語評価で見逃しが許容でき、CEO 留保を覆す根拠ができた後。別段階 |
| 分割で `carried_count` を 0 に戻す件 | 3.1 の親子 ID が見えるようになってから、連鎖が問題かをログで見る |
| exe 不能時の台帳移植 | 段階5で実 PC が該当してから |

## この計画がやらないこと

- Jev に日を閉じさせる、持ち越させる、取り下げさせる
- Jev に理由と分割タイトルを書かせる
- メール本文の既定送信
- Enter の既定選択肢を Jev の選択に差し替える
- Open-Jev を公式の代替経路にする
- 段階3.1より前にネットワーク呼び出しを足す
