# dayloop 開発計画（2026-09-22）

分析: [現状](../analysis/01-current-architecture.md)、[穴](../analysis/02-gaps.md)、[Jev の制約](../analysis/03-jev-constraints.md)、[製品価値](../analysis/04-jev-product-value.md)

## 方針

Jev を、計画・取り込み・途中確認・クローズ・振り返りの判断すべてに置く。本人が触るのは、確信が足りない残りと、1日1回の確定である。状態を書くのは Rust の台帳で、開いたタスクが残る日は閉じない。

キーが無い、または Jev が落ちた回は、今の全件質問に戻る。その経路は製品の中心ではない。中心は `decide` のサマリである。

自由文の理由は、理由コードに変える。変えないと Jev が判断を書けず、質問が残ったままになる。

## 段階

```
3.1 台帳と質問を一系統にする（Jev が書く提案の受け皿）
  → 3.2 判断を閉じた選択肢にし、Jev が提案を埋める（calibrate: 画面はサマリ、台帳は未反映）
    → 3.3 decide: 高い確信は提案として台帳の手前まで書き、確定の1回で反映する
      → 4 新しい Outlook は Edge。判断は同じ Jev
        → 5 VS Code はサマリと残りだけを出す
          → 6 会議・アラート・勤怠も Choice / Noul
            → 7 Copilot は残りの文章だけ。分岐は Jev 済みのサマリを読む
```

---

## 段階 3.1 台帳と質問を一系統にする

Jev の提案を載せる前に、合法手が一箇所であり、前日の未確定を台帳が拒否する状態にする。

### 3.1.1 前日未クローズは台帳が拒否する

- 変更: `src/store.rs` の `confirm_plan`、`src/engine.rs` の `plan_view`、`src/tools.rs` の `confirm_plan`
- `unclosed_days_before` に open タスクが残るあいだ、`confirm_plan` はエラーを返す
- `plan_view` はそのあいだ `confirm_plan` の質問を出さない
- テスト: 昨日が open のまま今日を `confirm_plan` すると失敗する。昨日を閉じたあと成功する

### 3.1.2 質問カタログを engine に寄せる

- 変更: `src/rituals.rs`、`src/tools.rs`
- `rituals` の選択肢文言を `engine::Question` の `options[].label` から出す
- MCP の description から `resolve_with` を消し、`options[].tool` と `needs` に合わせる
- テスト: `plan_day` / `check_in` / `close_day` / `retro_week` の説明に `resolve_with` が無い

### 3.1.3 親子、提案、スキーマ版

- 変更: `src/model.rs`、`src/store.rs`
- `Task.carried_from` を JSON に出す
- `proposed_state`、`proposed_reason_code`、`proposal_confidence` を足す。確定まで `state` は変えない
- 候補の status に `shelved` を足す。`shelved` は `rejected_refs` に書かない
- `user_version` でスキーマ版を持ち、既存 DB には足りない列を `ALTER` する
- テスト: 提案があっても `close_day` は open を残す（提案は open のまま）。確定関数が提案を `transition` / `carry_over` に変える

### 3.1.4 判断の前処理

- 追加: `src/facts.rs`
- 出力: `DueRelation`（`overdue` / `today` / `future` / `none`）、`Fit`（`fits` / `over` / `unknown`）
- 空き時間は予定の重なりを分にしてから見積と比べる。予定が無い日は `unknown`
- テスト: 予定 10:00–11:00、見積 30 分 → `fits`。見積 120 分 → `over`。期限が昨日 → `overdue`
- 祝日は段階6まで足さない

### 3.1.5 理由コード

- 追加: `src/reason.rs`
- コード: `waiting` / `blocked` / `no_time` / `not_needed` / `too_big`
- 日本語ラベル: 待ち / ブロック / 時間不足 / 不要 / 大きすぎる
- `state_reason` にはラベルを保存する。不変条件2はこの5つのどれかでも満たす
- 任意のメモ列 `state_note` は空でよい
- テスト: 理由コードだけで `not_done` と `carry_over` が成功する。コード外の空文字は失敗する

### 3.1.6 CI

- 追加: `.github/workflows/ci.yml`
- `ubuntu-latest` で `cargo test`
- COM の実機はジョブに入れない
- `scripts/smoke.sh` の既定バイナリを、存在する実行ファイル名にする

完了条件: CI が緑。`confirm_plan` が不変条件5を拒否する。提案だけでは日が閉じない。理由コードで持ち越せる。

## 段階 3.2 calibrate

画面はサマリにする。台帳の `state` はまだ Jev が変えない。帯の数値を決めるための段階で、製品の完成形は 3.3 である。

### 設定

```toml
[jev]
mode = "off"          # off | calibrate | decide
route = ""
timeout_ms = 2000
```

キーは `DAYLOOP_JEV_API_KEY`。サンプルには書かない。doctor はキーの有無と経路の到達だけを見る。件名は診断に使わない。

`off` またはキー無しでは、今の1件ずつの質問になる。

### クライアント

- 追加: `src/jev.rs`、`src/jev_prompts.rs`
- 関数は判断ごとに1つ。`classify_mail`、`propose_plan`、`propose_close`、`propose_check`、`gate_split`
- HTTP のフィールド名は採用 SDK の現行版で書く。スライドの説明用 JSON はコピーしない
- タイムアウト、401、429、529、接続失敗は `Unavailable`。その質問は人手に戻し、サマリに「Jev 不通 n 件」と出す
- 候補外のラベルは捨てて人手に戻す

### メール

state は件名（転送プレフィックス除去）、送信者の表示名、フラグ、未読、Rust が付けた事実ラベル。本文は既定で送らない。

1回の呼び出しにまとめる。

- Choice: `タスク候補` / `情報共有` / `要確認`
- Noul: 今日中の対応が必要か

`calibrate` では結果を `jev.log` とサマリに出し、候補の増減は今の `mail_hit` のまま。

### 計画・確認・クローズ

各 open タスクと各候補に Choice を聞く。閉じた選択肢は今の合法手に、理由が要る手には理由コードを足したもの。

- 計画: 今日にする / 未計画のまま / 棚 / 要確認
- 確認: 今日中にやる / 着手 / 持ち越し / 取り下げ / 要確認
- クローズ: 完了 / 未完了 / 持ち越し / 取り下げ / 要確認。完了以外には理由コードの Choice
- 持ち越し上限: 分割 / 取り下げ / 期限変更 / 要確認。分割タイトルはまだ人

`calibrate` の CLI は1件ずつ聞かない。サマリと「見てほしい」一覧を出し、確定は今の台帳状態に対してだけ行う（Jev の行は未反映である旨を行頭に書く）。

### 評価

- 追加: `fixtures/jev/ja-mail-20.toml` と `tests/jev_calibrate.rs`（HTTP はモック）
- 実 API は CI で呼ばない
- `docs/jev-eval.md` に、自分の日本語メール 20 件を帯ごとに数える手順を書く。`decide` の閾値はこの表が出てから `config.toml` に書く。英語の 0.9 は初期値にしない

完了条件: `calibrate` のサマリに Jev の内訳が出る。確定しても `state` は Jev の提案へ変わらない。API 失敗で `plan` / `close` が終了コード 1 にならない。

## 段階 3.3 decide

`mode = decide`。高い確信の行だけ提案列へ書き、サマリの確定1回で台帳へ入れる。

帯は `docs/jev-eval.md` の結果を `[jev] commit_confidence` に書く。それ未満と `要確認` は提案にしない。

- 情報共有かつ帯以上 → 候補は `shelved`。朝の質問から外し、`today` の棚件数に出す。7日で `retro` の質問に戻す。`rejected_refs` には書かない
- タスク候補かつ「今日」の Noul が帯以上かつ `Fit::fits` または `unknown` → 今日の `planned` を提案し、`confirm_plan` で反映する。`over` は今日に入れず未計画の提案にする
- クローズの Choice が帯以上かつ `要確認` でない → `proposed_state` と理由コード。`close` の確定で `transition` または `carry_over` を呼ぶ
- 残りの open が1件でもあると `close_day` は失敗する（不変条件1）
- `serve` はサマリ確定を `--yes` で実行してよいのは、見てほしい件数が 0 のときだけ。1件以上なら確定せず、通知は「見てほしい n 件」にする
- 分割: `DAYLOOP_LLM_ENDPOINT` が案のタイトルを2つ以上返す。`gate_split` の Noul が帯以上のときだけ提案に載せる。否、または LLM 無しなら人の質問のまま

完了条件: フィクスチャで、帯以上の情報共有が棚になり、帯未満が朝の残りに残る。残りが1件ある日は `close --yes` が終了コード 2。残り 0 の日は提案が反映されて閉じる。棚は 7 日後の retro に出る。

## 段階 4 新しい Outlook（Edge）

COM が無い、または新しい Outlook だけの PC。

- Edge 側はページを `MailItem` / `CalendarItem` に変換する。ページ全文は Jev に渡さない
- 認証は、ユーザーが既にサインインしている範囲で、管理者権限なしに取れる方式だけを調べる。取れなければ段階を止めて `docs/decisions.md` に残す
- 変換のあとの判断は段階 3.3 と同じ関数
- クラシック Outlook の Restrict 日付形式は、実機が触れるときに1回確認して決定事項へ書く

完了条件: Edge のフィクスチャが `ingest` を通り、`decide` のサマリ件数が COM フィクスチャと同じ規則で出る。

---

## 段階 5 VS Code 拡張

exe がポリシーで止まりうる PC 向け。

- 拡張は `dayloop mcp` を起動し、サマリと「見てほしい」だけを出す
- 確定ボタンは `confirm_plan` / `close_day`。残りが open のあいだ閉じた表示にしない
- exe が起動できない場合の台帳移植は、その PC が手元で確認できるまで始めない

完了条件: 残り 1 件の日は拡張から日が閉じない。残り 0 の日は提案どおり閉じる。

---

## 段階 6 会議・アラート・勤怠

取り込みを増やし、判断は Jev に乗せる。

- 会議準備の要否は Noul。開始時刻が 24 時間以内かは Rust
- 終了時刻を過ぎた予定は Choice（記録する / 棚 / 要確認）。終了したかは Rust
- アラートは `source = alert` で同じメール仕分けの Choice に入れる
- 勤怠の打刻失敗はタスクの open に混ぜない。別コマンドのまま
- 祝日を勤怠カレンダーで `next_workday` に足す。設定が無いときは土日だけ、今と同じ

---

## 段階 7 M365 Copilot

Copilot は生成側に限る。分岐は Jev と台帳がすでに持っている。

- Copilot が最初に読むのは `get_today` のサマリ（Jev が入れた数、棚、見てほしい、提案）
- 見てほしい件だけ、本人に聞いてツールを呼ぶ
- 理由の文章メモが要るときだけ下書きを書く。理由コードは Jev の提案を使う
- サマリの確定を、見てほしい件が残ったまま呼ばない

## 決定を後に残すもの

| 論点 | 決めるタイミング |
|---|---|
| ゲートウェイ（直販 / Vercel / Cloudflare / ロリポップ） | 対象 PC のプロキシ到達を見てから |
| `commit_confidence` の数値 | `docs/jev-eval.md` の20件の後。3.3 の実装条件 |
| 分割で `carried_count` を 0 に戻す件 | 3.1 の親子が見えてから |
| exe 不能時の台帳移植 | 段階5で該当 PC が確認できてから |

## この計画がやらないこと

- 見てほしい件が残る日を、Jev の提案だけで閉じること
- 棚を `rejected_refs` に入れて再掲不能にすること
- Jev に理由の文章、日付の比較、メールボックス全体の抽出をさせること
- メール本文の既定送信
- Open-Jev を公式の代替にすること
- 段階 3.1 より前にネットワーク呼び出しを足すこと
