# dayloop 開発計画（2026-09-22）

分析: [現状](../analysis/01-current-architecture.md)、[穴](../analysis/02-gaps.md)、[Jev の制約](../analysis/03-jev-constraints.md)、[製品価値](../analysis/04-jev-product-value.md)、[判断グラフ](../analysis/05-decision-graph.md)

## 方針

人が答えた内容は判断グラフの枝になり、同じ節は次から質問せず台帳まで進む。質問が残るのは、枝の無い節だけである。Jev はその初回の判断に使い、本人がその回答を一度採用したときだけ枝になる。Jev の出力だけでは枝を生やさない。

状態を書くのは Rust の台帳である。枝が選ぶのも、store がすでに許す選択肢と理由コードだけである。open が残る日は閉じない。

自由文の理由は理由コードにする。コードが枝に乗らないと、同じ持ち越しを翌日も文章で聞き続ける。

## 段階

```
3.1 台帳と理由コード（枝が呼ぶ合法手）
  → 3.2 回答を枝にし、同じ節は次から自動で適用する
    → 3.3 枝が無い節だけ Jev。採用された回答が枝になる
      → 4 新しい Outlook も同じグラフへ入る
        → 5 VS Code は新しい節だけを出す
          → 6 会議・アラート・勤怠も節と枝を増やす
            → 7 Copilot は枝の無い節の文章だけを書く
```

## 段階 3.1 台帳と質問を一系統にする

Jev の提案を載せる前に、合法手が一箇所であり、前日の未確定を台帳が拒否する状態にする。

### 3.1.1 前日未クローズは台帳が拒否する

- 変更: `src/store.rs` の `confirm_plan`、`src/engine.rs` の `plan_view`、`src/tools.rs` の `confirm_plan`
- `unclosed_days_before` に open タスクが残るあいだ、`confirm_plan` はエラーを返す
- `plan_view` はそのあいだ `confirm_plan` の質問を出さない
- テスト: 昨日が open のまま今日を `confirm_plan` すると失敗する。昨日を閉じたあと成功する

### 3.1.2 質問カタログを engine に寄せる

- 変更: `src/rituals.rs`、`src/tools.rs`
- `rituals` の選択肢文言を `engine::Question` の `options[].label` から出す
- MCP の description から `resolve_with` を消し、`options[].tool` と `needs` に合わせる
- テスト: `plan_day` / `check_in` / `close_day` / `retro_week` の説明に `resolve_with` が無い

### 3.1.3 親子、提案、スキーマ版

- 変更: `src/model.rs`、`src/store.rs`
- `Task.carried_from` を JSON に出す
- `proposed_state`、`proposed_reason_code`、`proposal_confidence` を足す。確定まで `state` は変えない
- 候補の status に `shelved` を足す。`shelved` は `rejected_refs` に書かない
- `user_version` でスキーマ版を持ち、既存 DB には足りない列を `ALTER` する
- テスト: 提案があっても `close_day` は open を残す（提案は open のまま）。確定関数が提案を `transition` / `carry_over` に変える

### 3.1.4 判断の前処理

- 追加: `src/facts.rs`
- 出力: `DueRelation`（`overdue` / `today` / `future` / `none`）、`Fit`（`fits` / `over` / `unknown`）
- 空き時間は予定の重なりを分にしてから見積と比べる。予定が無い日は `unknown`
- テスト: 予定 10:00–11:00、見積 30 分 → `fits`。見積 120 分 → `over`。期限が昨日 → `overdue`
- 祝日は段階6まで足さない

### 3.1.5 理由コード

- 追加: `src/reason.rs`
- コード: `waiting` / `blocked` / `no_time` / `not_needed` / `too_big`
- 日本語ラベル: 待ち / ブロック / 時間不足 / 不要 / 大きすぎる
- `state_reason` にはラベルを保存する。不変条件2はこの5つのどれかでも満たす
- 任意のメモ列 `state_note` は空でよい
- テスト: 理由コードだけで `not_done` と `carry_over` が成功する。コード外の空文字は失敗する

### 3.1.6 CI

- 追加: `.github/workflows/ci.yml`
- `ubuntu-latest` で `cargo test`
- COM の実機はジョブに入れない
- `scripts/smoke.sh` の既定バイナリを、存在する実行ファイル名にする

完了条件: CI が緑。`confirm_plan` が不変条件5を拒否する。提案だけでは日が閉じない。理由コードで持ち越せる。

## 段階 3.2 回答を枝にする

人が選んだ選択肢は、その場のタスクを更新したあと、判断グラフにも書く。次に同じ節が来たら Jev を呼ばず、枝の選択肢で store を呼ぶ。詳細は [判断グラフ](../analysis/05-decision-graph.md)。

### 保存

- 追加: `src/graph.rs`
- テーブル `graph_nodes`（kind, key）と `graph_edges`（from_id, to_choice, reason_code, support, active, updated_at）
- 節は件名、状況、送信者、取り込み元。キーは [判断グラフ](../analysis/05-decision-graph.md) の表
- 既存 DB へは 3.1 のスキーマ版で `ALTER` と `CREATE TABLE` を足す

### 書き込み

- 変更: `src/tools.rs` と `src/rituals.rs` の、人が選択肢を確定したすべての経路
- 回答の直後に、件名の節と状況の節へ active な枝を書く。同じ選択肢なら `support` を増やす。違う選択肢なら旧枝の `active` を外し、新しい枝を active にする
- 送信者の節は、同じ送信者で同じ選択肢が 2 回続いたときに active にする。1 回で送信者全体を変えない
- キーワード規則や Jev が先に書いた状態には、この時点では枝を生やさない

### 読み取り

- 追加: `fn resolve(facts) -> Option<Edge>`。順は件名、状況、送信者。親どうしが割れていて件名も状況も無いときは `None`
- `plan` / `check` / `close` / `intake` は、`Some` ならその枝で store を呼び、質問を出さない
- `None` の行だけを質問にする
- 適用したタスクに `decided_by`（`graph:<edge id>`）を残す
- 追加コマンド `dayloop revise <id>`。直近の自動適用を別の合法手へ変えると同時に枝を差し替える

### テスト

- 「経費精算」を時間不足で持ち越したあと、同じタイトルの次のタスクは質問なしで持ち越す
- その直後に `revise` で取り下げると、3件目は質問なしで取り下げになる
- 送信者の枝が棚とタスクで割れていて件名の枝が無いメールは、自動で棚にもタスクにもしない
- 枝が全件に当たった日は `close` が質問なしで成功する。1件でも未知なら終了コード 2

完了条件: 同じ件名への2回目の質問が出ない。`revise` の次の件から新しい枝が適用される。Jev はまだ呼ばない。

## 段階 3.3 枝の無い節だけ Jev

Jev は `resolve` が `None` の行だけに呼ぶ。人がその結果を採用したとき、3.2 と同じ関数で枝が生える。次回その節は Jev を通らない。

### 設定

```toml
[jev]
mode = "off"          # off | on
route = ""
timeout_ms = 2000
```

キーは `DAYLOOP_JEV_API_KEY`。`off` またはキー無しでは、枝が無い行は人手の質問のまま。枝がある行の自動適用は `off` でも動く。グラフはローカルなので、Jev が落ちても既知の節は進む。

### 呼び出し

- 追加: `src/jev.rs`、`src/jev_prompts.rs`
- メールの未知節: Choice `タスク候補` / `情報共有` / `要確認` と、Noul「今日中の対応が必要か」
- タスクの未知節: その場面の合法手。理由が要る手には理由コードの Choice を同じ呼び出しに積む
- state に足してよいグラフは、その送信者の active な枝が1本あるとき、その選択肢だけ。グラフ全件は渡さない
- 本文は既定で送らない
- タイムアウト、401、429、529 は質問に戻す。既知の枝の適用は止めない
- 候補外ラベルは捨てて質問に戻す。枝には書かない

### 採用

- Jev が `要確認` を返した行は質問にする。回答が枝になる
- `要確認` 以外はサマリに「新しい節」として1行出す。`serve` は未知が 0 件の日は通知しない。1件以上ならその件数だけ通知し、自動では閉じない
- 人がサマリで採用するか、個別に選び直すと枝が生える。採用前に台帳へは書かない
- 情報共有を採用したら棚。`rejected_refs` には書かない。7日後の retro で同じ枝を維持するか、選び直す
- 分割タイトルは、枝が「大きすぎる」のときだけ生成 LLM に書かせ、Jev の Noul が否なら質問に残す。採用されたタイトル対は、元タイトルの節から子タイトルへの枝として残す

### 評価

- `tests/jev_unknown.rs` は HTTP をモックする。実 API は CI で呼ばない
- `docs/jev-eval.md` は、未知の日本語 20 件で Jev の Choice と人の回答が一致した帯を数える手順。`[jev]` に帯を書くのはこの表のあと。帯より下は採用サマリに出さず質問にする
- 英語の 0.9 は初期値にしない

完了条件: 未知の件名は一度だけ聞き、同じ件名の翌日は Jev のモックが呼ばれない。Jev 不通でも既知の枝は適用される。未知が残る日の `close --yes` は終了コード 2。

## 段階 4 新しい Outlook（Edge）

COM が無い、または新しい Outlook だけの PC。

- Edge 側はページを `MailItem` / `CalendarItem` に変換する。ページ全文は Jev に渡さない
- 認証は、ユーザーが既にサインインしている範囲で、管理者権限なしに取れる方式だけを調べる。取れなければ段階を止めて `docs/decisions.md` に残す
- 変換のあとは 3.2 の `resolve` を先に通し、枝が無い行だけ 3.3 の Jev に渡す
- クラシック Outlook の Restrict 日付形式は、実機が触れるときに1回確認して決定事項へ書く

完了条件: Edge のフィクスチャが `ingest` を通り、一度採用した送信者の次のメールは質問なしで同じ枝になる。

## 段階 5 VS Code 拡張

exe がポリシーで止まりうる PC 向け。

- 拡張は `dayloop mcp` を起動し、枝が無い節だけを出す。既知の節は件数だけ出す
- そこに答えると枝が増え、同じ節は一覧から消える
- exe が起動できない場合の台帳移植は、その PC が手元で確認できるまで始めない

完了条件: 同じ件名に2回目のカードが出ない。未知が1件残る日は拡張から日が閉じない。

---

## 段階 6 会議・アラート・勤怠

取り込みを増やし、それぞれの回答を節と枝にする。

- 会議準備の要否は、初回だけ Noul。開始時刻が 24 時間以内かは Rust。人が「準備する」と答えた会議名は、次から枝でタスクになる
- 終了時刻を過ぎた予定は、初回だけ Choice（記録する / 棚 / 要確認）。終了したかは Rust
- アラートは `source = alert` の節を足し、同じグラフを通す
- 勤怠の打刻失敗はタスクの open に混ぜない。別コマンドのまま
- 祝日を勤怠カレンダーで `next_workday` に足す。設定が無いときは土日だけ、今と同じ

## 段階 7 M365 Copilot

Copilot は、枝が無い節の文章だけを書く。

- 既知の節はグラフがすでに台帳まで進めている。Copilot はそこを聞き直さない
- 未知の節だけ本人に聞き、回答は 3.2 の枝になる
- 理由の文章メモが要るときだけ下書きを書く。理由コードは枝か、その場の Choice を使う
- 未知が残ったまま日を閉じる呼び出しはしない

| 論点 | 決めるタイミング |

## この計画がやらないこと

- Jev の出力だけで枝を生やすこと
- 枝が無い節が残る日を、質問なしで閉じること
- 棚を `rejected_refs` に入れて再掲不能にすること
- Jev に理由の文章、日付の比較、メールボックス全体、グラフ全件を渡すこと
- メール本文の既定送信
- Open-Jev を公式の代替にすること
- 段階 3.1 より前にネットワーク呼び出しを足すこと
