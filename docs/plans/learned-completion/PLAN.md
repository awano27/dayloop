# 同名タスクへの完了判断再利用を止める

対象: `codex/requirements-gap` / `17e3abf6757b674a1ea732529ba4a5a10f330875`。
依頼: 開発ブランチの現状を確認し、既存変更を保護して修正・回帰検証する。実装は Luna、設計・統合レビューは親エージェント。

## 保護と範囲（修正・検証時点）

- 着手時の変更は `README.md`（追跡済み変更）と `docs/issues.md`（未追跡）のみ。内容を変更せず、SHA256を前後比較する。
- 修正対象は学習済み `done` の自動再適用とその回帰テスト。既存履歴・DBスキーマを削除または移行しない。
- 今回のタスクへの明示的な完了・修正、今回の参照に一致する観測証跡による完了、既存の相手待ち保護は維持する。
- `carry` / `drop` / `not_done` / `start`、候補分類、並び順、および未知タスクへの新規Jev判断の仕様変更は対象外。
- 本番台帳・画面・実APIには触れない。コミット・pushは行わない。

## 実装契約と手順

1. 現状の関連テストとClippyをオフラインで確認し、失敗があれば基準結果として残す。
2. Lunaが同名の別IDタスクでの回帰テストを先に追加・更新し、修正前に失敗することを確認する。
3. 学習済み完了は履歴として保持するが、新しいタスクへ自動適用しない。既存DB内の `done` にも同じ規則を適用する。
4. 過去の `done` が一致したときは未完了を維持し、より一般的な枝や新規Jev判定へ迂回して完了させない。通常の日次確認へ残す。
5. グラフ適用とJev経由の既知判断再利用を同じ契約で保護する。明示操作が使う共通処理まで一律に無効化しない。
6. 親エージェントが差分・境界条件をレビューし、必要な修正はLunaへ戻す。最終版の全テストとClippyを実行する。

## 受入条件

- 手動完了または明示的な `revise done` の後、同名・空白正規化で同名の別タスクは未完了のまま。
- 旧形式の保存済み完了判断を再読込しても自動完了しない。元の完了履歴は失われない。
- グラフ、Jevの既知判断経路、CLI/MCPの日次確認で同じ結果になり、未回答があれば日次終了は拒否される。
- 新規Jev結果をモックし、過去の `done` からJev再判定に迂回しないことを確認する。
- 今回の明示的な完了と正しい参照の観測完了は機能し、持ち越し・候補・相手待ちの既存テストを壊さない。
- 合成データと隔離した `DAYLOOP_HOME` でのみ検証する。実際の資格情報や外部CLIをテストへ渡さない。
- 保護対象ファイルのハッシュが一致し、差分が修正とテスト・本計画に限定される。
