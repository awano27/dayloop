# 5 営業日実利用トライアル

## 目的

このトライアルは、5 つの実際の営業日に dayloop を使い、朝・昼・夕方・週次の運用と失敗時の復旧を記録するためのテンプレートである。自動テスト、合成データ、プロセス再起動試験、1 日だけの動作確認は 5 営業日実利用の Pass ではない。

実業務データを使うか、専用の合成データだけを使うかを開始前に選ぶ。両者の記録は混ぜない。外部サービス・クラウド AI・自動起動を使う場合は、それぞれ本人の別の明示承認を得る。

通常の手動起動は次の製品コマンドを使う。`<専用DAYLOOP_HOME>` は開始前に確認した絶対パスである。

```text
<exe> serve --quiet --data-dir <専用DAYLOOP_HOME>
```

HKCU startup は、このトライアルを始めるだけでは有効化しない。必要な場合は [WINDOWS_ACCEPTANCE.md](WINDOWS_ACCEPTANCE.md) の本人確認チェックポイントを通過してからにする。

## 日ごとの運用契約

| phase | 本人が行うこと | 期待する dayloop の動作 | Pass の根拠 |
|---|---|---|---|
| 朝: plan | `plan` または MCP の `plan_day` を確認し、質問に回答する | 未閉鎖日、候補、予定、レビューを提示する。本人未回答では候補採用、タスク完了、計画確定、日次閉鎖をしない。日次準備と質問保留は保存し得る | 入力・回答・結果を記録 |
| 昼: check | `check` または MCP の `check_in` を確認する | 進行中・未着手・未回答を提示する。本人未回答では候補採用、タスク完了、計画確定、日次閉鎖をしない。日次準備と質問保留は保存し得る | 入力・回答・結果を記録 |
| 夕: close | `close` または MCP の `close_day` を確認する | open / required review が残れば閉じず questions を返す | close 成否と未回答の扱いを記録 |
| 週次: retro | 金曜に `retro` または MCP の `retro_week` を確認する | 集計と質問を返す。本人確認後だけ note を保存する | note の確認・保存有無を記録 |

CLI と MCP のどちらを使ったかを各行に書く。MCP では `plan_day` と `list_reviews` が日を準備する。`prepare_day` という MCP ツールはない。

復旧は、表示されたエラー、`serve.log`、`notify.txt`、`serve-state.json`、`ledger check --json` に基づいて行う。根拠のない設定変更、外部サービスへの再送、既存データの削除、別 exe への切替は記録なしに行わない。

## 最終判定

5 日を Pass とするには、次を全て実際の記録で満たす必要がある。

1. 5 つの営業日を完了し、各日のデータ区分、exe SHA、専用 home、phase ごとの結果が記録されている。
2. 朝・昼・夕方の phase で、回答と無回答の扱いが確認されている。
3. 未回答、通知失敗、プロセス再起動などの少なくとも一つの異常・復旧経路を、実際の証拠とともに記録している。
4. 実業務データ、合成データ、外部サービス、cloud profile の結果を区別している。
5. 未実施の項目を Pass とせず、`Unknown` または `Fail` を残している。

クリーン Windows、OS 再起動、スリープ復帰、実クライアント GUI、外部サービス接続、署名・公開は別の受入項目であり、5 日の記録だけから Pass としない。
